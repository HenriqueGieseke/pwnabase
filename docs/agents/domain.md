# Domain docs

This repository uses a single domain context.

Before exploring domain behavior, read GLOSSARY.md and relevant
decisions in docs/adr/. Proceed when optional files are absent.

Use the glossary's domain vocabulary. Surface conflicts with
existing decisions explicitly.

Record agreed requirements in DESIGN.md. Keep glossary entries
focused on domain definitions. Create ADRs when a decision involves
a meaningful trade-off, is costly to reverse, and needs explanation.
